# Local matrix design

`POST /matrix` parses a strict, bounded JSON contract into an immutable request. The engine validates axis and cell budgets, acquires a bounded request slot, resolves the configured street profile, and snaps exact distinct coordinates with that profile's weighting and subnetwork filter. The policy uses an empty snap-prevention list, matching the explicitly equivalent reference `/route` request. Invalid points retain their input positions.

The flexible backend builds one complete request-local QueryGraph from both axes before searching. Exact repeated origin coordinates share a row search; distinct coordinates are never merged by proximity. Destination node IDs form a set, so repeated destinations do not alter termination. Results scatter back to every original row and column. `auto` selects flexible. The reference backend calls the existing in-process two-point `GraphHopper.route`, with plain Dijkstra and CH/LM disabled. It remains an independent routing oracle.

## Search invariants

* **Direction and turn history.** Node-based profiles key the best label by adjacent node. Profiles with turn costs key it by upstream directed edge traversal ID and carry the incoming edge. Two arrivals at one junction therefore remain distinct when their legal continuations or turn penalties differ. Edge iteration and both upstream weight/time helpers use forward direction. Edge-based U-turn permission comes from the weighting; node-based immediate reversal follows upstream Dijkstra's exclusion.
* **Cost objective and metrics.** Each immutable label contains double weight, long milliseconds and double distance obtained by extending the same selected predecessor. Weight determines improvements and queue order. Time and distance never choose the route. Accepted transition weight must be finite and nonnegative; inaccessible positive infinity is skipped. Nonfinite accumulated metrics and long duration overflow fail the whole request. Source labels have no incoming edge, so no departure turn is charged; settling a target charges no later arrival turn.
* **Settled-state correctness.** The heap orders immutable labels by weight with deterministic state/sequence ties. An improvement inserts a replacement; the old label is ignored unless it still matches the best-state map by identity. For finite nonnegative transitions, a minimum valid label popped from the queue cannot have a cheaper undiscovered continuation into that state: such a continuation would have required a predecessor of no greater weight to be processed first. Thus popped valid labels have optimal state weight, including zero-cost transitions.
* **Target correctness.** A destination is finalized only when its first valid arrival state is settled. With an unconstrained endpoint this is the minimum over all its arrival states. It is removed from the remaining-target set exactly once and never overwritten. The initial source label handles the zero-length source target. Settled targets continue to expand while other targets remain. Once all targets settle, the result is complete; otherwise only frontier exhaustion establishes disconnection.
* **Incomplete work is an error.** Interruption, deadline expiry and visited-state exhaustion throw a whole-request failure. They cannot produce an unreachable cell or partial numeric success. Checks occur between heap operations and while scanning outgoing edges. Each search receives the remaining aggregate visited-state budget. Reference requests also receive remaining limits; an upstream response without measured search counters fails because its aggregate budget cannot be accounted for.

Snaps at interior points retain virtual edges and partial distances. Each search receives the QueryGraph-wrapped weighting exactly once. Combined and two-point QueryGraphs may split different edges, changing geometry-derived distances and per-edge duration rounding. `precision-notes.md` documents the fixed-fixture investigation; tests require independent path evidence for each out-of-tolerance difference.

## Profiles and concurrency

Only configured static street profiles and their imported access, directional speeds, restrictions, subnetworks and configured custom models are supported. Runtime custom models, PT/departure time, headings, curbsides, point hints, pass-through and arbitrary request hints are rejected by the public contract. The profile determines node- versus edge-based traversal. Neither the base graph nor the existing route implementation is modified by matrix calls.

Searches within one request run serially on the HTTP request thread. Admission limits the total number of active matrix requests; excess requests receive service saturation. Each request creates its weighting, snaps, QueryGraph and counters. Each source search creates its own explorer, labels and heap. Mutable search objects and virtual IDs are never shared between requests. The engine's shared state is the read-only imported graph, immutable limits/provenance and the admission semaphore. Fingerprints hash loaded graph content and configured profile/engine identity once per engine, rather than per request or cell.

## Space and work bounds

Let `M,N` be the input axis lengths, `K` the requested metric count, `U` the number of distinct input coordinates, `S` the reachable traversal states, and `R` the number of successful label relaxations for a source search. Requested output storage is `O(K*M*N)` boxed numbers/list references. Duplicate mappings, snaps and the request overlay use `O(M+N+U)` storage. Disconnected-pair hints can themselves require `O(M*N)` storage.

One serial source search keeps `O(S)` best-state entries and up to `O(R)` queued labels, including stale replacements. It returns at most `O(N)` target metrics. Normal searches do not retain predecessor chains or extract a path per cell. Explicit test diagnostics retain predecessors and export directed edge evidence. Source search state is released between rows, so peak search storage is for one source rather than the sum over all origins. Concurrent request memory is multiplied by the bounded number of admitted requests; the imported base graph is shared.

For node-based traversal, states are nodes and transitions are directed adjacent edges. For edge-based traversal, states are directed arrival edges and transitions include allowed incoming/outgoing edge combinations at each junction; their count can exceed the base edge count. A lazy-heap search performs work proportional to examined transitions plus `O(R log R)` queue operations. Flexible invokes this once per distinct valid origin coordinate and stops early when all targets settle. These are structural bounds, not a claim of lower latency or memory than prepared CH routing; measured comparisons belong in the benchmark report.
